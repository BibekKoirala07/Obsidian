The Chinchilla Scaling Law
The idea is years old and it was published by Google. but it seems like idea isn't as simple as it was previously thought. The name Chinchilla is there cuz their model at the time was called Chinchilla. It was the model that came after another model called gopher. The main idea was how do you scale models ? How do we go from 8 billion parameter to 16 billion parameters and get twice the performance from it ? Their discovery was that we need to scale the training data in proportional way. Like if double the number of parameter then requirements would be double the training token that was used. If you are getting diminishing return from training even with more training data, then it is the sign that you need to increase the number of parameters. Same with vice versa, If you are doubling the number of weights, then this law suggest we need twice the data also. This rule still helps but it is less emphasized nowadays. Particularly for two reasons. One reason is that we have found how to squeeze more and more information into a model without increasing the number of parameters. Like using better training techniques through filtering out of what they call pruning the number of weights in the model and through better architecture. Another reason is now inference time techniques have become so prominent this idea that getting better performance from a model isn't just about what we do from training time, it's also so much what we do at inference time. More reasoning using techniques like rag. Less emphasis on training data for performance. So people tak less about chinchilla scalling law
