# 🧠 1. What a Load Balancer _Really_ Is

At scale, a load balancer is:

> A **traffic control system** that decides:
> 
> - _Where_ a request goes
>     
> - _When_ it goes
>     
> - _Whether_ it should go at all
>     

It’s not just “round robin”.

It’s a **gatekeeper**.

---

# 🧱 2. Where It Lives in Real Systems

Typical modern flow:

```
Client
  ↓
CDN
  ↓
L7 Load Balancer / Reverse Proxy (Nginx / Envoy)
  ↓
API Gateway (optional)
  ↓
Service Load Balancer (K8s / ALB)
  ↓
Backend Pods
```

You often have **multiple LBs**.

Not one.

---

# 🧠 3. Layer 4 vs Layer 7 (Very Important)

### 🟢 L4 (Transport Level)

Works on: TCP/UDP

Sees only:

```
IP + Port
```

Example:

- AWS NLB
    
- HAProxy TCP mode
    

Features:

- Very fast
    
- No HTTP logic
    
- No headers
    
- No auth
    

Use when:

> You want raw speed.

---

### 🟢 L7 (Application Level)

Works on: HTTP/HTTPS

Sees:

```
URL
Headers
Cookies
JWT
Body (sometimes)
```

Example:

- Nginx
    
- Envoy
    
- ALB
    
- API Gateway
    

Features:

- Routing
    
- Auth
    
- Rate limit
    
- Rewrites
    

Use when:

> You want intelligence.

Most backends use L7.

---

# 🧱 4. Load Balancing Algorithms (Beyond Round Robin)

### 1️⃣ Round Robin

```
A → B → C → A → B
```

Bad if servers differ.

---

### 2️⃣ Weighted Round Robin

```
A(3) B(1)
A A A B
```

Used in prod.

---

### 3️⃣ Least Connections (Very Important)

Send to server with fewest active requests.

Used when:

- Long requests
    
- Streaming
    
- WebSocket
    

### 4️⃣ Consistent Hashing (Advanced)

Route based on:

```
userId → hash → server
```

Why?  
→ Cache locality  
→ Sticky behavior

Used in big systems.

# 🧠 5. Health Checks (Core of Reliability)

LB is useless without this.

Every few seconds:

```
/health
/ready
```

LB asks:

> “Are you alive?”

If fail → removed.

### Types:

- Active: LB polls
    
- Passive: detects failures
    

Good systems use both.

---

# 🧱 6. Sticky Sessions (Session Affinity)

Problem:

If sessions stored in memory:

```
User → A (login)
Next → B (lost session ❌)
```

Fix:

LB pins user → same server.

Methods:

- Cookie
    
- IP hash
    

Downside:

- Bad for scaling
    
- Bad for failover
    

Better:  
→ Use Redis sessions.

---

# 🧠 7. TLS Termination (Why LB Handles HTTPS)

Instead of:

```
Every backend does TLS
```

Do:

```
Client ↔ LB (HTTPS)
LB ↔ Backend (HTTP)
```

Why?

- Less CPU
    
- Central cert mgmt
    
- Easier rotation
    

This is standard.

# 🧠 9. Load Balancer vs API Gateway (Real Difference)

|Feature|Load Balancer|API Gateway|
|---|---|---|
|Routing|Basic|Advanced|
|Auth|Rare|Yes|
|Rate limit|Basic|Yes|
|Transform|No|Yes|
|Business logic|No|Light|

Rule:

> LB = traffic  
> Gateway = policy
